# Faulty Medical Devices — End-to-End Analysis

Analysis of the [ICIJ Faulty Medical Devices Global Dataset](https://www.kaggle.com/datasets/vladimirmijatovic/faulty-medical-devices-global-dataset):
medical device recalls, safety alerts and field safety notices reported worldwide.

The project is now a reproducible pipeline:

```
raw CSV  ->  clean tables  ->  merge  ->  metrics  ->  static dashboard
```

The final deliverable is a self-contained dashboard in `dashboard/` (`index.html` + `styles.css` + `app.js`).
No Power BI, no database, no server: open the HTML file and explore.

| Clean device records | 30,556 |
| Clean manufacturer records | 31,790 |

| Date range | 1997-06-01 → 2018-07-09 |
| Peak year | 2017 (2,773 recalls) |

- **Risk classification:** Class II dominates with 24,256 device-linked recalls, followed by Class I (5,589), Class III (2,094), Unclassified (269) and HDE (16).
- **Most recalled manufacturer:** Customed, Inc. (695), followed by Siemens Medical Solutions USA (481) and Stryker Howmedica Osteonics (476).
- **Most recalled product category:** Orthopedic Devices (5,397), followed by Cardiovascular Devices (4,203) and General & Plastic Surgery Devices (4,051).
- **Distribution scope:** of the 32,224 device-linked recalls, 10,646 were nationwide, 8,132 worldwide/international, 8,086 both nationwide and international, and 5,360 regional/local/other.
- **Data validation:** 13/13 automated checks pass (unique ids, complete device table, allowed risk/implant values, parsed dates, join coverage and report consistency).
- **Countries in the events table:** United States (35,822), Australia (3,551), United Kingdom (136), India (11). The device-linked subset is United States only, because complete device rows come from the FDA source.

These numbers are regenerated by the pipeline and embedded in the dashboard.

## Quick start

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# Full pipeline: read data/raw, rebuild data/processed and dashboard/app.js
python -m src.pipeline
```

## Pipeline stages

### 1. Extract

`src/extract.py` locates the newest file matching each prefix in `data/raw/` and loads it with pandas
(`low_memory=False`, UTF-8).

### 2. Transform

Rules are applied by `src/transform.py` and mirror the exploratory notebooks:

| Table | Rules | Result |
|---|---|---|
| `devices` | drop rows with any null; drop `updated_at` and `number`; unify `Not Classified` → `Unclassified`; drop constant/duplicate columns (`country`); deduplicate | 118,249 → 30,556 rows |
| `events` | drop 11 link/date/text columns; keep rows with ≥15 of 19 remaining values; drop `date`, `documents`, `action_summary`, `action_classification`; parse `date_initiated_by_firm`; deduplicate | 124,969 → 39,520 rows |
| `manufacturers` | drop columns with >40% nulls (`address`, `comment`, `representative`); drop `updated_at`; drop rows without `name`; deduplicate | 31,827 → 31,790 rows |

Every step reports how many rows/columns were removed, and the result is stored in
`data/processed/etl_report.json`.

### 3. Validate

`src/validate.py` runs 13 explainable checks after cleaning and merging:

- primary keys are unique in `devices`, `events` and `manufacturers`;
- the devices table is complete and `manufacturers.name` is populated;
- `risk_class` and `implanted` only contain allowed values;
- at least 95% of event dates parse correctly;
- at least 75% of events link to a device (currently 81.5%);
- every matched device resolves a manufacturer;
- `event_id` is unique after the merge and `event_country` is populated;
- the row counts in the ETL report agree with the dataframes.

The result is stored in `data/processed/etl_report.json` and rendered in the dashboard's
"Automated validation" panel.

### 4. Merge

`src/merge.py` joins events to devices on `events.device_id → devices.id` and devices to manufacturers
on `devices.manufacturer_id → manufacturers.id`.

- `data/processed/eventsEnriched.csv` — **left join**, all 39,520 recalls. The `has_device` flag marks the
  32,224 recalls with a cleaned device record. This is the dashboard source.
- `data/processed/mergedDevicesEvents.csv` — **inner join** (32,224 rows), kept for compatibility with the
  notebook analysis.

Column names are de-duplicated (`event_id`, `device_name`, `manufacturer_name`, …) and
`date_initiated_by_firm` is a real datetime.

### 5. Metrics

`src/metrics.py` collapses the enriched table into a compact cube:

- Dimensions: year, country, risk class, implant status, classification, determined cause,
  manufacturer, device name and normalized distribution scope. Long tails are folded into
  `Other (grouped)`; missing values become `Unknown`.
- Facts: one row per dimension combination with a count.
- The unfiltered dashboard contains ~7,900 fact rows, which keeps `app.js` small and lets every filter run
  instantly in the browser.

### 6. Dashboard

`src/dashboard.py` injects the metrics JSON into `src/templates/app.js` and writes `dashboard/app.js`.
The three dashboard files are the only artefacts a user needs.

## Methodology and principles

### Data analysis

- The business questions are defined in `notebooks/00_project_overview.ipynb` before any cleaning.
- The exploratory notebooks document schema audits, missing values, cardinality, distributions and the
  relationship between risk class and implant status.
- Every dashboard KPI and chart is derived from the cleaned tables through `src/metrics.py`; there are no
  hard-coded numbers.
- Free-text fields are normalized transparently: device names lose the `Device Recall` prefix, long tails are
  folded into `Other (grouped)`, and `distributed_to` is mapped to four distribution scopes.

### Data cleaning

- Cleaning rules live in code (`src/transform.py`), not only in notebooks, and are applied in a fixed order.
- Each rule is documented in the README, the notebook notes and the ETL report.
- Missing values are handled explicitly (complete-case devices, ≥15 non-null events, >40% null columns dropped).
- Types are enforced: dates are parsed, IDs are joined as integers, low-cardinality strings become categories.
- Duplicates and constant/duplicate columns are removed, and inconsistent labels are unified
  (`Not Classified` → `Unclassified`).
- `src/validate.py` verifies uniqueness, completeness, allowed values, join coverage and report consistency.

### Organization and reproducibility

- Raw data is immutable in `data/raw/`; everything under `data/processed/` is regenerated.
- Configuration and paths are centralized in `src/config.py`, independent of the current working directory.
- One command rebuilds all processed files and the dashboard: `python -m src.pipeline`.
- `--skip-etl` rebuilds only the dashboard from the enriched CSV.
- The notebooks are consolidated documentation; they are not required to reproduce the results.
- The dashboard is static and self-contained: three files, data embedded in `app.js`, no server or database.
- `.gitignore` excludes raw/processed CSVs and the Kaggle archive; the dashboard data is versionable
  because it is aggregated.

## Data notes and limitations

- **Selection bias:** the clean device table comes from a complete-case filter. It keeps rows with all fields
  populated, which mostly belong to US FDA records; the enriched subset is therefore United States only.
  The dashboard states this explicitly and still reports all 39,520 recalls in the timeline and country views.
- **Missing dates:** 973 recalls have no parsable `date_initiated_by_firm`. They count in totals but not in
  the year trend.
- **Manufacturer identity:** `manufacturers.name` is not unique (20,049 distinct names over 31,790 ids).
  Counts use the id; the display name is shown as-is.
- **Top-N folding:** manufacturer, device, classification and cause charts show the top 15 values and group the
  rest as `Other (grouped)`.
- **Distribution scope:** `distributed_to` is free text with more than 11,000 distinct values. It is normalized
  with explicit rules (nationwide / worldwide / both / other), not with a geographic gazetteer, so the four
  buckets are directional rather than authoritative.
- **Parent companies:** `parent_company` is 41.9% null, so it is kept in the enriched CSV but not charted.
- **Device names:** the `Device Recall` prefix is removed before ranking.
- **Country codes:** ISO-3 codes are mapped to readable names (USA → United States, etc.).
